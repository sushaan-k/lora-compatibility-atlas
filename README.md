# The LoRA Compatibility Atlas — code and data release

Reproducibility package for *When Do LoRAs Merge? A Compatibility Atlas for LoRA Libraries* (TMLR submission): every experiment driver, analysis script, panel config, and released result the paper draws on.  Every headline number in the paper recomputes from the artifacts in this repository; `MANIFEST.sha256` lists all files with checksums.

## Layout

- `reproduce.py` -- entry point; forwards to the public PEFT compatibility runner (`peft_atlas_lite/run_peft_atlas_lite.py`).
- `peft_atlas_lite/fixed_chart_probe.py` -- shared-chart Helly audit script used for the scaled Qwen probe.
- `peft_atlas_lite/configs/` -- one config per panel (`multifamily/{tinyllama_12x,mistral7b_10x,phi2_10x,pythia410m_10x,pythia1b_10x}.json`, plus `tinyllama_12x_fp16.json` for the effective-rank diagnostic), the `fixed_chart_helly_qwen.json` audit config, four balanced/circulant Qwen $m{=}50$ slice configs under `qwen_m50_slices/` (`qwen_m50_{balanced,circulant}_seedNN.json`), and `smoke.json`, a three-adapter TinyLlama subset for an end-to-end check. Each carries the adapter list and seeds; license metadata is included where machine-readable fields were available, and repository identifiers are provided for auditability.
- `scripts/` -- the analysis scripts the paper cites by name, including the deployed-loss envelope measurement (`deployed_envelopes.py`, which takes `--carto/--gains/--out` so the same computation runs on any dense chart set), the scale-series uncertainty analysis (`scale_panel_ci.py`, which asserts it reproduces the published aggregates before computing intervals), and the scale-series rank diagnostic (`scale_adim.py`).
- `experiments_gpu/` -- GPU experiment drivers (`expA`--`expK`) with panel configs and task files; `GPU_RUNBOOK.md` documents the runs.
- `results_public/` -- every result directory the paper draws on: the Qwen $m{=}50$ panels (`qwen25_m50_balanced`, 4,000 events; `qwen25_m50_facepairs`; `dare_linear_qwen_m50`), the five smaller base panels (`tinyllama_12x`, `mistral_10x`, `phi2_10x`, `pythia410m_10x`, `pythia1b_10x`), the `tinyllama_stability` threshold/seed sweep, the Mistral answer-token results (`answer_token_panel`, `answer_jets`, `answer_panel_m8`, `cartography`, `deployed_envelopes`), shared-chart and scale runs (`shared_chart_decision`, `shared_chart_decision_m50`, `scale_m16`, and the amortized-index scale series `scale_m30` and `scale_m50`, each carrying the raw jets, held-out validation rows, the analysis, its adapter-block bootstrap and leave-one-adapter-out intervals in `scale_ci.json`, and the strict spectral-rank diagnostic in `sigma_adim.json`), the fixed-chart Helly probes (`fixed_chart_helly`, `fixed_chart_helly_500`), effective-rank diagnostics (`effective_rank_strict`), foundations, intervention, and calibration outputs (including the fifteen-query deployed coefficient test under `intervention_15q/` and the equal-access supervised comparison `qwen25_m50_balanced/supervised_same_probe.json`), and the maintenance records (`maintenance/`).

The four Qwen slice configs under `peft_atlas_lite/configs/qwen_m50_slices/` use short names (`qwen_m50_{balanced,circulant}_seedNN.json`); the `slice_id` strings inside `results_public/qwen25_m50_balanced/results.csv` use the original long run names, and each config's seed field gives the correspondence.  One caution for re-analysis: the `margins` column of every released `results.csv` records per-member margins measured on the held-out validation run (the sign of the minimum margin reproduces the feasibility label), so it must never be used as a screening-time feature; the fitted-side quantities are `predicted_score`, `primal_upper`, `dual_lower`, and `certificate_gap`.  `scripts/supervised_baselines.py --feature_modes same_probe` shows the intended equal-access construction.

## Verification status

Every headline number in the paper recomputes from the artifacts in this archive; `scripts/scale_panel_ci.py`, `scripts/m16_fidelity_ci.py`, and `scripts/qwen_cheap_baselines.py` assert or print their reproductions directly.  Six claim groups rest on artifacts that predate the public release and are not contained here: the KnOTS SVD-screener comparison, the cosine-baseline table's cached comparison slices, the coefficient-floor sweep (`tab:alpha_sweep`), the license-family column of the manifest table (which reflects Hugging Face model cards at audit time), the TinyLlama cold-start GBM replication's feature and fold specification, and the $m{=}10$ TinyLlama sub-library jets behind one effective-rank sentence.  Their published values are unchanged from the original runs; everything else regenerates.  The pair-vs-triple phenomena table's original pair-label join is likewise not recoverable ($70$ duplicated pair keys carry conflicting held-out labels across slices); the caption discloses this and the conclusion is join-invariant.

## Hardware

GPU runs on a single AMD MI300X (192 GB HBM3), ROCm 7.0, vLLM with `tensor_parallel_size=1`, bf16 weights. CPU analyses run on any x86_64 host with the dependencies in `peft_atlas_lite/requirements.txt`.

## Licenses

Public model and adapter references come from Hugging Face repositories whose cards reported Apache-2.0 or MIT licenses at audit time. Per-adapter repository identifiers (`name`, `repo`, `probe_key`, `task`) are in each config's `adapters` field; weights and adapters are not redistributed. No private data, scraped user data, or human-subjects data are used.
